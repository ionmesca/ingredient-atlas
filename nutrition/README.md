# Reviewed nutrition supplements

`overrides.json` is the versionable canonical source for reviewed supplements. It contains exact Atlas IDs, food/state/unit, seven-field baseline and compare-and-set hash, the proposed eighth field, its public USDA source, and the reviewer/date/change ID. It contains no Buna IDs, operational receipts, private review notes or image provenance.

The three supported supplements are salted butter (FDC173410), mature raw dry chickpeas (FDC173756), and raw expressed coconut milk (FDC170172). They add only absent saturated fat. They do not make unsalted, cooked/canned, light or drinking products equivalent. USDA table values are published source values; butter/chickpea saturated rows use derivation49 “Calculated”; coconut's derivation is unspecified. All three have zero data points, which does not mean zero saturated fat or a fresh laboratory measurement.

Run `node src/nutrition-sync.mjs --journal <catalog-journal.jsonl> --change <exact-change-id>` to check an independently accepted bound intent. This is dry-run by default. `--write` applies only nutrition and field evidence to the full internal/public manifests and records the canonical override. `--mode readback` reads the result. Undo requires `--mode undo --result-hash <exact-applied-hash>`; add `--write` to execute. Conflict, pending review, known zero, identity/origin mismatch, or changed evidence stops the operation.

`receipts.private.json` holds operational apply/undo state and the complete dual-target intent, including private Buna bindings. It is ignored and excluded from the published package. A fresh checkout needs only the public canonical source to retain values and provenance on rebuild. If an update stops partway through, rerun the same apply/undo; only the exact before/after states are accepted. Inspect unexpected edits rather than deleting the receipt or guessing a baseline.

The local default builders are destructive image/export workflows. This nutrition adapter never invokes them, creates images, contacts Buna, or publishes anything. Existing JSONL/Parquet and compact manifests have no nutrient values, so this supplement preserves them unchanged; original source labels and FDC IDs also remain unchanged. Builder hooks use `loadOverrides` and `overlayRecord` after source selection to preserve the canonical supplement even when a live Buna profile takes preference. The hooks are captured as bounded patches in the catalog implementation receipt because these local build scripts were already ignored by Git.

Buna applies its own internal transactional adapter separately. The two systems do not share a transaction: read both, apply each exact reviewed intent, read both back, retain receipts and use CAS undo if needed. No claim of dual-target completion is warranted until both readbacks pass.
